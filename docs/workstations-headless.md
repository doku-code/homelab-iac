# Headless pve-lab workstations

## Contract and ownership

The operator retired the physical workstation GPU/USB/KVM model on 2026-10-24.
Terraform keeps the same five resource addresses, disks, EFI/TPM, identities,
CPU/RAM and NICs. It now declares standard VGA (32 MiB), virtual tablet and no
hook. Stale private hardware profiles requesting passthrough fail validation.
No workstation PCI/USB assignments can be generated by this root.

The existing Ansible host role converts the explicitly named existing guests
501/502/503/601/602 using supported digest-guarded Proxmox operations and verifies
that every other configuration field remains unchanged. It fails before writes
on identity mismatch, pending changes, a running affected guest, unexpected
hardware/hook or another mapping consumer. VM504/603 are outside the boundary.
Cluster mappings used solely by this pool are retired. VM templates are not
recreated or changed. GPU-specific templates and exclusivity automation are gone.

Host cleanup removes only the old role-owned VFIO/blacklist/GRUB files, its
marked initramfs module block and GPU-binding service/script. Standard Proxmox
package configuration (including its nvidiafb blacklist), IOMMU and AMD iGPU
are preserved. Initramfs and GRUB are regenerated; configured Proxmox boot ESPs
are refreshed only when present. No runtime PCI unbind or automatic reboot.

## Maintenance interface

```sh
make workstations-check
# After reviewing output, stopping affected guests and accepting maintenance:
make workstations-bootstrap WORKSTATIONS_HEADLESS_APPROVED=yes
```

Strict SSH trust remains required. The role does not shut down guests. Bootloader
changes require a separately approved controlled reboot. Review running guests,
RAM, cluster/quorum and management access first; never adjust expected votes
automatically. Removal of hardware exclusivity is not a RAM admission controller:
five 16-GiB guests cannot all run safely on this 32-GB host.
During sequential tests both VM501 and VM503 reported 192.168.0.51 with distinct
preserved MAC addresses. Do not run them concurrently before reviewing guest
addressing/DHCP identity; this conversion intentionally does not change networking.

## Firmware and physical test boundary

Observed board: ASUS ProArt B850-CREATOR WIFI NEO, BIOS1002 (2026-07-13).
The OS exposes no firmware-attributes interface. Do not claim the actual
firmware halt-on-error/primary-display policy was read or changed.
Leave the installed GPU in place for the first power+Ethernet-only test.
The operator must verify POST completes without display or USB input.
If POST waits for input, inspect BIOS keyboard/error-prompt handling and the
primary-display/iGPU selection using local setup. Exact menu availability must
be checked on this BIOS; do not change storage/boot/Secure Boot settings blindly.
Removing the discrete GPU later is a separate physical compatibility test.

Remote guest console validation is not physical monitorless POST evidence.
No new GPU driver installation, Windows reinstallation or disk conversion is
part of this procedure. Existing signed/basic virtual display drivers are the
first compatibility path.

## Guest compatibility observation

VM501 initially had a black virtual console despite a healthy Microsoft Basic
Display Adapter (PCI VEN_1234/DEV_1111). Its pre-existing software Virtual Display
Driver, ROOT\DISPLAY\0000, was also active. Through the existing guest agent,
the supported PowerShell command below disabled only that identified adapter:

```powershell
Disable-PnpDevice -InstanceId 'ROOT\DISPLAY\0000' -Confirm:$false -ErrorAction Stop
```

The Windows lock screen then appeared on the virtual console. No driver was
uninstalled or downloaded. This is a persisted guest compatibility correction,
not a blanket action for other VMs. Before repeating it after an OS restore,
read Get-PnpDevice/Get-CimInstance Win32_VideoController and verify the exact
adapter identity; never disable the working Microsoft console adapter.
Enable-PnpDevice on the same identified device reverses the change if required
for a deliberately restored streaming setup.
